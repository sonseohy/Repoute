# 13. 실험 E5 — 따라가기 질문 20개, quality agent (12와 비교) (Phase 3, 2026-10-21)

## 방법

- **n = 20** 질문 (`evals/datasets/walkthrough_questions.json`, 레포 4개), 질문마다 체크포인터 없이 새 상태로 실행.
- **모델**: agent = gpt-4o (quality), finalize = gpt-4o (openai), temperature 0. 프롬프트 v3.
- **유효·구체·def줄**: 최종 답 인용을 `citation_validity`·`citation_specificity`·`citation_at_def` 로 사후 채점.
- **엄격**: 최종 `validation_errors` 가 0개이고 인용이 1개 이상(그래프 검증 = 존재 + read_code 로 읽은 범위 안). 사후 유효성은 파일:줄 존재만 보므로 엄격 통과를 주 지표로 본다.
- **읽기**: 실제 실행된 read_code 호출 수("이미 읽은 범위" 차단·상한 미실행 제외).
- **도달**: `expect_reach`(사람이 코드를 보고 정한 기대 도달 심볼)가 어떤 단계의 제목·설명 또는 인용 심볼 문자열에 들어 있는지 보는 **자동 근사치**. 사람 판정 아님.
- **차단**: "이미 읽은 범위" 로 막힌 read_code 수. **도구**: 실행된 도구 호출 수.
- **탐색차단**: 읽기 없이 탐색만 6회 한 뒤 실행하지 않은 find_* 수(예산은 소모).
- **비용**: `UsageMetadataCallbackHandler` 토큰 × 스크립트 `PRICES` 단가 추정치. LangSmith 태그 `wt-batch` 로 교차 확인. **시간**: invoke 벽시계(인덱싱 제외).

1. **quality 는 과정 강제 장치가 한 번도 필요 없었다.** 탐색 차단 0, 넛지 0. 10~12 에서 fast 를 위해 만든 장치들은 quality 에게는 안전망일 뿐이다. 반대로 fast 는 장치 없이는 65% 가 근거 없는 답, 장치를 넣으면 얕은 답. **모델 급은 "체인을 따라가는 판단" 자체를 바꾼다**(wave10a 의 "짧고 정형적인 단계만 저가 모델" 원칙이 ReAct 에서는 "도구 선택은 정형적이지 않다" 로 읽힌다).
2. 수동 보정: requests-03 은 `models.py:576 [prepare_body]` 를 인용했으니 도달(자동 판정이 `PreparedRequest.` 접두어를 못 맞춤). 미도달 7건 중 requests-05(`BaseAdapter.send` 까지, 기대 `HTTPAdapter.send`), rich-03(`_render_buffer` 까지, 기대 `_write_buffer`), httpx-05(`_send_handling_redirects` 까지, 기대 transport 의 예외 변환) 는 **한 단계 못 미친** 경우다. 15회 예산을 다 쓴 건(requests-05, httpx-05, click-05 등 6건)이 많아, 예산 20~25 로 늘리면 도달이 더 오를 가능성이 있다(다음 실험 후보).
3. **비용 판단**: 질문당 $0.083 은 기획서의 레포 지도 목표($1/레포)와 비교하면 충분히 작고, 학습 도구에서 "끝까지 답하는가" 가 "싸게 답하는가" 보다 중요하다. `repoute ask` 기본값은 quality 로 유지(이미 기본값). fast 는 `--agent-model fast` 로 남긴다. 후속 후보: 하이브리드(fast 로 시작, 탐색 차단이 발동하면 quality 로 승격).
4. 시간이 더 짧은 이유: 턴 수(9.9 vs 11.9)와 재작성 0. 단가가 아니라 턴 수가 지연을 결정한다.
5. **Phase 4 로 넘기는 것**: 도달 판정을 끝 이름 매칭으로 바꾸기(자동 12 → 수동 13 의 차이), `expect_reach` 를 호출 체인 전체(순서 포함)로 확장해 `call_chain_accuracy` 계산, 이 20개를 LangSmith 데이터셋 `walkthrough-qa` 로 등록.
