# 06. 프롬프트 v3 회귀 측정 — 레포 5개 유효성·구체성 (Phase 2, 2026-10-21)

## 방법

- **n = 5** 레포, 모드 2개(naive=`validate=False`, validate=검증 루프, 재생성 상한 2회)
- **모델**: fast = gpt-4o-mini, quality = gpt-4o (openai), temperature 0. 프롬프트 v3.
- **합성 입력**: 모듈마다 `인용 가능한 줄: 이름:줄, ...` 목록(심볼 없는 모듈만 `1(모듈 시작)`)과 검증 오류별 힌트(`→ 인용 가능한 줄`·`비슷한 경로`)를 넣는다. 03·04 기록 이후 모든 프롬프트 공통으로 바뀐 입력이라, 그 결과와는 프롬프트 외에 이 점도 다르다.
- **인용 유효성**: 두 모드 모두 최종 guide 의 인용(진입점 + 각 단계 ref)을 `citation_validity`·`validate_citations` 로 사후 검증 (naive 는 루프 없이 결과만 채점).
- **인용 구체성**: `citation_specificity` = 유효하면서 그 파일의 심볼 범위 안을 가리키는 인용 비율 (심볼 없는 파일은 줄 1 도 인정).
- **토큰**: `UsageMetadataCallbackHandler` 로 그래프 안 LLM 호출을 모델별 합산.
- **비용**: 스크립트의 `PRICES` 단가로 계산한 추정치. LangSmith(태그 `e4`)의 비용과 교차 확인 가능.
- **시간**: 그래프 `invoke` 의 벽시계 시간(perf_counter). 인덱싱·clone 제외.

## 관찰

- **Phase 2 완료 기준 충족.** 레포 5개(파일 17~541개) 모두 유효성 100%·구체성 100%, 재생성 0회. 평균 $0.022, 7.6초. 기획서 목표(5분, $1)의 각각 2.5%, 2.2% 수준이라 비용·시간은 병목이 아니다.
- 03(E4) 과 비교: 유효성 평균 97% → 100%, fastapi 재생성 2 → 0. 03 에는 구체성 지표가 없어 직접 비교는 fastapi(83% → 100%)만 가능. 다른 4개 레포의 03 인용은 raw 에 refs 가 없어 재채점 불가(이 기록 이후 raw 에 refs 가 남으므로 다음부터는 가능).
- 인용 목록을 보면 click 은 `core.py:1496/1506/1515`, rich 는 `live.py:111`, `progress.py:1168` 처럼 실제 함수·클래스 줄을 가리킨다. 심볼 없는 파일(`fastapi/__init__.py:1`)만 줄 1.
- **여전히 남은 것은 "인용이 맞는가" 가 아니라 "순서가 좋은가" 다.** requests 진입점은 여전히 `help.py:126 main`(troubleshooting 10, 미해결), 읽기 순서는 PageRank 순에 가깝다(troubleshooting 11). 이것은 Phase 4 의 정답 데이터셋(`reading-guide-gold`)과 `entrypoint_recall`·`core_module_precision@5` 로만 측정할 수 있다. 유효성·구체성 100% 는 "근거가 틀리지 않는다" 까지만 보장한다.
- 비용 누적: 이 실험 $0.11, 프로젝트 전체 약 $0.42.
