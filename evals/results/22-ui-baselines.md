## A. Supervisor 의도 분류

- **n = 30** 메시지(`evals/datasets/supervisor_intents.json`, map 9 / ask 9 / next 6 / chat 6, has_guide·history 포함). 라벨은 Opus 에이전트 초안을 사용자가 검수("라벨 그대로").
- **방법**: `evals/experiments/supervisor_intents.py` — classify 노드와 같은 프롬프트(`supervisor_v2.CLASSIFY`) + 같은 게이트(`_gate`)를 메시지마다 1회. LLM 단독 결과와 게이트 적용 후 결과를 따로 기록. LangSmith 태그 `ui-baseline-intents`.

| | LLM 단독 | 게이트 적용 후 |
|---|---|---|
| 정확도 | **29/30 (97%)** | **28/30 (93%)** |
| map | 8/9 | 9/9 |
| ask | 9/9 | 7/9 |
| next | 6/6 | 6/6 |
| chat | 6/6 | 6/6 |

게이트 적용 3건: 고침 1(si-06 "다음"·지도 없음: LLM next → map), **망침 2**(si-13 "리디렉트 처리는 어디서 해?", si-14 "인증 헤더는 어떤 순서로 붙어?": LLM ask → 게이트가 "함수 이름 없음" 으로 map).
비용 호출당 $0.00009(입력 평균 480 토큰), 지연 평균 1.0s.

**관찰**
- fast 모델의 분류 자체는 이 표본에서 거의 틀리지 않는다. 유일한 LLM 오답(지도 없는 "다음" → next)은 게이트가 잡았다.
- **지금 가장 큰 오류원은 LLM 이 아니라 "ask 인데 식별자 없음 → map" 게이트다.** 사용자가 "어디서 해?" 라고 물으면 읽기 지도가 통째로 다시 나온다. 이 2건이 Phase 5.5-4(심볼 임베딩 검색 도구 + 게이트 완화)의 **전(before) 값: 함수 이름 없는 ask 0/2 통과**.
- next 6/6 은 전부 `NEXT_PATTERN`/`SEEN_STEP_PATTERN` 에 걸리는 문장이라 LLM 과 무관하게 맞는다. 정규식에 안 걸리는 next 표현("계속", "그 뒤엔?")은 데이터셋에 없어 측정되지 않았다.
- 한계: n=30, 라벨 초안이 에이전트. "LangGraph 가 뭐야?"(si-29) 처럼 식별자처럼 보이는 일반 질문은 LLM 이 chat 으로 맞췄지만, 틀렸다면 게이트가 못 잡는다.

## B. /explain 설명 품질 — 프롬프트 v1 vs v2

- **n = 20 심볼** (requests·httpx·click·rich 각 5, `walkthrough_questions.json` 의 `chain_evidence` 근거 줄을 감싸는 함수·메서드; 3~137줄, docstring 있음 18 / 없음 2). 중복 심볼 5개 건너뜀.
- **조건**: v1 = "핵심 로직 줄 / 주의할 분기·예외 / 호출하는 중요 함수 **중에서 고른다**", v2 = "**첫 항목은 반드시 핵심 로직 줄**, 나머지는 두 종류 중에서". 다른 문구 동일. 캐시 비움(`.repoute_cache/evals/explain_quality.sqlite`).
- **방법**: `evals/experiments/explain_quality.py`. 자동 지표(LLM 없음): `ref_validity`(항목의 "(줄 N)" 이 심볼 범위 안, 줄 참조 없는 항목은 무효), `has_ref_rate`, `count_ok`(2~4개), `docstring_ko_ok`, `first_is_def_or_doc`(첫 항목이 def/docstring 줄 — 핵심 로직 아님의 보수적 신호). 보조: fast 모델 판정 "첫 항목이 핵심 로직 줄인가".

| 지표 | v1 (n=20) | v2 (n=20) |
|---|---|---|
| watch 항목 수 합 | 56 | 82 |
| **카테고리 이름을 그대로 쓴 항목** ("핵심 로직 줄 (줄 N)") | **56/56 (100%)** | **0/82** |
| 줄 참조 있는 항목 | 56/56 (100%) | 71/82 (87%) |
| 줄 참조 유효(범위 안) / 참조 있는 항목 | 52/56 (93%) | 63/71 (89%) |
| ref_validity (심볼별 평균, 참조 없음 = 무효) | 0.93 | 0.78 |
| count_ok (2~4개) | 19/20 | 18/20 |
| docstring_ko_ok | 20/20 | 20/20 |
| first_is_def_or_doc | 2/20 | 0/17 |
| fast 판정 "첫 항목 = 핵심 로직" | 20/20 | 20/20 |
| 비용 (설명 + 판정) | $0.0089 | $0.0093 |
| 토큰 설명 in/out | 27.5k / 2.1k | 27.8k / 2.5k |

**관찰**
- **v1 은 내용이 없었다.** 56개 항목 전부가 프롬프트의 카테고리 이름("핵심 로직 줄", "호출하는 중요 함수")을 그대로 복사하고 줄 번호만 붙였다. 사용자가 UI 에서 "핵심 로직 줄이 안 나온다" 고 느낀 원인은 항목이 빠진 게 아니라 **항목이 라벨뿐이어서 무엇을 보라는지 알 수 없었던 것**이다. 지표(ref_validity 0.93, count_ok 19/20)로는 전혀 보이지 않았다 — 다시 Goodhart(04).
- **v2 는 실제 코드 줄을 쓴다** (`resp = self.send(prep, **send_kwargs) (줄 651)`). 대가는 형식 흐트러짐: 줄 참조 없는 항목 11개(httpx `get`/`request` 는 코드와 "(줄 N)" 을 **별도 항목으로 쪼갰고**, `Client.send` 는 3개 항목에 참조 생략), 항목 수 초과 2건(최대 8개).
- **판정 모델은 쓸모없었다.** v1 의 라벨뿐인 항목에도 20/20 "핵심 로직 맞음". 같은 fast 모델이 자기 계열 출력을 평가하면 변별력이 없다. 보조 지표로도 쓰지 않는다(다음부터 제거하거나 quality 모델·사람 판정으로).
- **네 자리 줄 번호의 천 단위 잘림**: `Command.make_context`(1359~1394) 는 v1·v2 모두 "(줄 390)", "(줄 393)" 처럼 1 을 떨어뜨렸고(6/6 전부), `Command.__call__` 은 "(줄 1686~688)". 범위 밖 참조 12개 중 7개가 이 유형. 프롬프트가 아니라 **출력 후 결정론적 보정**(범위 밖이면 line_start 의 천 단위를 더해 범위 안이면 채택)이 맞는 해결 — 입력/도구 층 원칙.
- 아주 짧은 심볼(3줄 `Command.__call__`, `Console.__exit__`)에서는 v2 가 범위 밖 이웃(`def main`, `class Console`)을 끌어온다. 2~4개를 채우라는 규칙이 3줄 함수에는 과하다 — 항목 수 하한을 심볼 길이에 맞추는 것이 다음 후보.

**결론**: v2 를 기본값으로 유지(이미 적용). 다음 변경은 (1) 줄 번호 천 단위 보정과 참조 없는 항목 병합(결정론적, LLM 0), (2) 짧은 심볼의 항목 하한 완화. 측정은 이 스크립트를 같은 20개 심볼로 재실행(약 $0.01, 판정 끄기 `--no-judge`).

## C. 결정론적 후처리 적용 후 (같은 날, LLM 호출 0 · $0)

B 의 형식 결함 셋을 `normalize_watch`(참조만 있는 항목을 앞 항목에 병합 → 범위 밖 줄 번호에 line_start 의 천 단위를 더해 범위 안이면 채택 → 4개 상한)로 고치고, **B 와 똑같은 LLM 출력**(캐시)에 적용해 같은 스크립트로 재채점. 판정 모델은 끔.

| 지표 | v1 전 → 후 | v2 전 → 후 |
|---|---|---|
| 문제 항목(참조 없음 + 범위 밖) / 전체 | 4/56 → **0/56** | 19/82 → **9/75** |
| ref_validity (심볼별 평균) | 0.93 → **1.00** | 0.78 → **0.88** |
| has_ref_rate | 1.00 → 1.00 | 0.90 → **0.95** |
| count_ok | 19/20 → 19/20 | 18/20 → **20/20** |

- 천 단위 잘림 7건은 전부 복구됐다(`Command.make_context` 1390·1393·1386~1388, `Command.invoke` 1436~1444).
- v2 에 남은 9건: `Client.send` 의 참조 없는 항목 3개(병합할 짝이 없음), 3줄 심볼(`Command.__call__`, `Console.__exit__`)이 이웃 `def`/`class` 를 끌어온 범위 밖 참조 — 프롬프트 "2~4개" 가 3줄 함수에 과한 것이라 다음 변경 후보(심볼 길이에 따른 항목 하한).
- 캐시에서 읽을 때도 같은 후처리를 적용하므로 이미 저장된 행도 UI 에서 같은 모양으로 나온다.
