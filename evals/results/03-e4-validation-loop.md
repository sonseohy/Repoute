# 03. 실험 E4 — 인용 검증 루프 유무 (Phase 2, 2026-10-21)

## 방법

- **n = 5** 레포, 모드 2개(naive=`validate=False`, validate=검증 루프, 재생성 상한 2회)
- **모델**: fast = gpt-4o-mini, quality = gpt-4o (openai), temperature 0. 프롬프트 v1.
- **인용 유효성**: 두 모드 모두 최종 guide 의 인용(진입점 + 각 단계 ref)을 `citation_validity`·`validate_citations` 로 사후 검증 (naive 는 루프 없이 결과만 채점).
- **토큰**: `UsageMetadataCallbackHandler` 로 그래프 안 LLM 호출을 모델별 합산.
- **비용**: 스크립트의 `PRICES` 단가로 계산한 추정치. LangSmith(태그 `e4`)의 비용과 교차 확인 가능.
- **시간**: 그래프 `invoke` 의 벽시계 시간(perf_counter). 인덱싱·clone 제외.

## 관찰

- **가설 "검증 루프가 환각률을 줄인다"는 이 표본(n=5)에서 지지되지 않았다.** naive 도 이미 유효 비율 97%(5개 중 4개 레포 100%)였고, validate 모드의 평균도 97%로 같다. 프롬프트 v1 이 "입력으로 준 심볼 줄 번호만 인용"하도록 강하게 제한해서, 루프 없이도 대부분 맞는다. 검증 루프의 가치는 "틀린 인용을 사용자에게 내보내지 않는다"는 안전장치 쪽에 있고, 정확도 향상은 이 데이터로는 주장할 수 없다.
- **유일한 실패(fastapi)는 루프가 고치지 못했고 비용만 2.6배 늘었다** ($0.022 → $0.057, 재생성 2회). LangSmith 트레이스로 확인한 실패 인용은 `fastapi/__init__.py:0`. 이 파일은 import 만 있고 함수·클래스 정의가 없어 프롬프트에 넣어 준 심볼 줄 번호가 하나도 없었고, 모델은 0번 줄을 지어냈다. 피드백 "파일은 25줄까지"를 받고도 세 번 모두 같은 `:0` 을 냈다. 즉 **피드백 메시지가 "무엇이 틀렸는지"만 말하고 "대신 무엇을 써야 하는지"를 말하지 않아 재생성이 소용없었다.**
- 개선 후보(다음 실험, 프롬프트 v2 = E6): (1) 심볼이 없는 모듈은 "줄 1(모듈 시작)"을 인용 가능한 위치로 프롬프트에 명시, (2) 줄 번호는 1 이상이라고 명시, (3) 검증 오류 메시지에 "이 파일에서 인용 가능한 줄: …" 힌트를 붙여 피드백. fastapi 만 다시 돌려 비교하면 약 $0.05.
- **비용 교차 확인**: 스크립트 추정(PRICES)과 LangSmith 비용은 대체로 ±5% 안이고, fastapi validate 만 추정 $0.0565 vs LangSmith $0.0429 로 차이가 컸다. 재생성 때 같은 프롬프트 접두어가 반복되어 OpenAI 의 캐시 입력 할인(저렴한 단가)이 적용된 것으로 보인다. 추정치는 상한으로 보면 된다.
- **시간**: httpx naive 21.6s 는 1회성 지연(다른 9회는 7~14s). 평균 8~10s 로 기획서 목표(5분)와 거리가 멀어 시간은 병목이 아니다.
- 총 비용: 10회 합계 약 $0.25 (LangSmith 기준 $0.229).
