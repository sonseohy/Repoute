# 04. 실험 E6 — 프롬프트 v2와 "줄 1 인용 가능" 입력 변경 (Phase 2, 2026-10-21)

03(E4)에서 fastapi 만 실패한 원인(`fastapi/__init__.py:0`, 심볼 없는 모듈을 인용할 방법이 없었음)을 고친 뒤 fastapi 만 다시 측정. **결과는 "유효성 지표는 고쳐졌지만 인용 품질은 나빠짐"** 이다.

## 방법
- **n = 1** 레포(fastapi/fastapi@6f28852, 541 files, targets 22), validate 모드, 재생성 상한 2회. 모델 fast gpt-4o-mini / quality gpt-4o, temperature 0.
- 변경 두 가지를 분리해서 측정:
  - **입력 변경(v1·v2 공통)**: 합성 프롬프트의 모듈별 "인용 가능한 줄" 목록 앞에 항상 `1(모듈 시작)` 추가, 검증 오류에 "이 파일에서 인용 가능한 줄: …" 힌트 추가.
  - **프롬프트 문구 변경(v2 만)**: 줄 번호 ≥ 1, 심볼 없는 모듈만 줄 1 인용, 힌트 뒤의 값에서 다시 고를 것.
  - 실행 A = 프롬프트 v1 + 입력 변경(통제군), 실행 B = 프롬프트 v2 + 입력 변경. 비교 기준 = 03 의 fastapi validate(프롬프트 v1, 입력 변경 전).
- 유효성은 `citation_validity`(사후 검증). **구체성**은 이 기록 직후 추가한 `citation_specificity`(심볼 범위 안을 가리키는 인용 비율, 심볼 없는 파일의 줄 1 은 인정)로 `evals/experiments/rescore_specificity.py` 가 04 raw 를 재채점한 값. 03 은 raw 에 refs 가 없어 04 에 적힌 인용 목록을 같은 함수로 채점.
- raw: `04-e6-prompt-v1-control.json`, `04-e6-prompt-v2.json`. 비용은 스크립트 추정과 LangSmith 둘 다 기재.

## 관찰
- **고친 효과는 입력 변경에서 나왔다.** 통제군(v1 문구 그대로)도 100%·재생성 0회다. 프롬프트 v2 의 문구는 이 표본(n=1)에서 측정 가능한 차이를 만들지 않았다. "심볼 없는 모듈만 줄 1" 이라는 v2 의 명시적 지시도 지켜지지 않았다(exceptions.py 등은 심볼이 있는데 줄 1 인용).
- **지표는 올랐지만 인용 품질은 떨어졌다.** 03 에서는 7개 중 0개가 줄 1 이었고 `routing.py:129` 처럼 실제 함수 줄을 가리켰다. 입력에 "1(모듈 시작)" 을 넣자 모델이 5/7 을 줄 1 로 바꿨다. 유효하지만 "어디를 읽으라는 것인지" 정보가 사라진 인용이다. **citation_validity 만 최적화하면 이렇게 된다** — 측정하지 않는 품질이 깨진다(Goodhart). 이 프로젝트의 평가 설계에 "유효성" 과 별도로 **"구체성(심볼을 가리키는 인용 비율)"** 지표가 필요하다는 것이 이 실험의 가장 큰 산출물이다.
- 비용은 재생성이 사라져 $0.043 → $0.022 로 절반. 시간도 13.7s → 7~8s.
- 다음: (1) `citation_specificity` 추가 완료, 03·04 재채점 결과가 위 표(83% → 43%), (2) 프롬프트 v3 = "줄 1 은 그 파일에 심볼이 없을 때만 허용" 을 입력 쪽에서 강제(심볼이 있는 파일의 인용 가능 목록에는 줄 1 을 넣지 않음), (3) fastapi 1회 재측정(약 $0.025) 으로 유효 100% 를 유지하면서 구체성이 03 수준(≈100%)으로 돌아오는지 확인.
